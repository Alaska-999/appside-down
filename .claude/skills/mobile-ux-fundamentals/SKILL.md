# Mobile UX fundamentals

Загальноприйняті мобільні практики, обов'язкові для кожного екрана поверх візуальної мови elements-v1. Порушення будь-якого пункту — привід зупинити апрув мокапа чи порту.

## Touch & ergonomics

- Ціль дотику ≥44×44 pt завжди; візуально менші контроли добирають зону через hitSlop (лінза 44 вже мінімум; toggle 52×31 + hitSlop 7; sm-кнопка 42 + hitSlop 2).
- Головна дія — в нижній третині екрана, в зоні великого пальця (мокап: кнопка на `68 + 16 + safe-area` від низу). Деструктивні дії — далі від зони звичного тапу, ніколи не поруч із primary.
- Safe area через `useSafeAreaInsets()`/структурний паддінг — ніяких вгаданих констант під нотч/home-indicator.
- Свайпи не конфліктують: горизонтальний свайп картки ↔ вертикальний скрол — жест-хендлери з activeOffset; edge-back iOS не перекривати власними жестами.
- Один primary CTA на екран; другорядні дії — ghost/secondary.

## Feedback & responsiveness

- Кожен тап дає миттєву відповідь (<100ms): press-scale (card .982, row .978, button .965, icon .92) + hapticTap. Немає «мертвих» натискань.
- Оптимістичний UI для швидких мутацій; для довгих — стан loading прямо в кнопці (spinner + disabled), не блок-оверлей.
- Завантаження списків/екранів — skeleton, не спінер. Спінер лише всередині кнопки.
- Помилка — під конкретним полем (11.5 `#FCA5A5`), глобальні збої — toast/state-екран з дією «Try again». Порожній стан завжди має CTA (як «Nothing found → Create a module»).
- Pull-to-refresh на списках, які синхронізуються з бекендом.

## Navigation & structure

- Таб-бар: 3–5 пунктів, активний стан очевидний (градієнтна pill), лейбли завжди видимі.
- Back завжди передбачуваний: chevron зліва вгорі + iOS swipe-back; модальні флоу закриваються X зліва (як у мокапі Create), з Save праворуч.
- Деструктивне підтвердження — sheet/alert з явним red-варіантом і Cancel (мокап: «Delete this module?» — той самий шит, кросфейд 200мс).
- Стан скролу зберігається при поверненні на екран; заголовок екрана не стрибає.
- Клавіатура: інпут ніколи не ховається під нею (KeyboardProvider вже в проєкті); поле у фокусі підскролюється; тап поза полем ховає клавіатуру; правильні keyboardType/autoComplete/textContentType (email, one-time-code для OTP).

## Forms

- Лейбл над полем, не placeholder-як-лейбл (placeholder — приклад значення).
- Валідація: onBlur або на сабміт, не на кожен символ з першої літери; помилка зникає щойно виправлено.
- Лічильники лишку (52/200) з'являються заздалегідь і попереджають кольором (#FCD34D) ДО ліміту.
- OTP: автофокус, авто-перехід між клітинками, paste всього коду, resend-таймер.
- Кнопка сабміту доступна одразу (disabled тільки коли очевидно чому), стан loading в ній самій.

## Motion & attention

- Максимум один анімований елемент у видимій області (правило мокапа). Рух — нагорода за дію, не фонова розвага.
- Тривалості: press 160–170ms, стандартні переходи 200–420ms, cubic-bezier(.2,.8,.3,1); нічого важливого не ховати за анімацією довшою за ~400ms.
- `useReducedMotion()` — статичний 0%-стан для всіх декоративних анімацій.
- Числа-лічильники добігають синхронно зі своєю дугою/смугою (розбіжність 100ms помітна).

## Accessibility & polish

- Контраст тексту ≥4.5:1 для body (муted #8FA8B8 на base — тільки для другорядного, ніколи для критичного тексту/цін/помилок).
- accessibilityRole/Label на інтерактивних елементах; стани (selected/disabled) передані не лише кольором — є іконка/позиція/текст (мокап: статус = колір лампи, але у рядку є і зірочка/лічильники).
- Динамічний текст не обрізається: заголовки ellipsis з numberOfLines, кнопки не ламаються від довших лейблів (укр/англ).
- Тап-цілі не впритул: ≥8pt між сусідніми інтерактивними елементами.
- 60fps: важкі Skia-фони — один canvas, без ре-рендерів від стану екрана; списки — FlashList/FlatList з мемоізованими рядками.
